## Constraints on applying this checklist

1. **`packages/builder` uses Tailwind v4.** Items there may be checked against the literal utility classes named below.
2. **`packages/renderer` is dependency-free** with its own token stylesheet (`packages/renderer/src/stylesheet.ts`). Audit it by **principle only** — spacing ratios, type hierarchy, contrast — never by class name. Every class-specific item below carries a *Principle:* line; that line is the renderer-facing form of the check.
3. **Seed findings** this checklist must catch (they are called out inline where covered):
   - **(a)** Helper text touching the field above it when re-editing a filled wizard step → §1 and §5 spacing items.
   - **(b)** Secondary buttons ("We don't need one") that neither stand out nor match the button design system → §4 hierarchy items and §6 consistency items.

Where an item says "8px", "12px" etc., that is the pixel value at the default 16px root; the token form is what matters.

## 1. Spacing scale

The entire v4 spacing system derives from one token, `--spacing: 0.25rem`; utilities multiply it: `p-4` = 4 × 0.25rem = 1rem, `m-8` = 2rem, `w-16` = 4rem ([theme docs](https://tailwindcss.com/docs/theme)).

- [ ] **Every margin/padding/gap is a multiple of the base unit (0.25rem / 4px).** Builder: only `--spacing`-derived utilities (`p-*`, `m-*`, `gap-*`, `space-*`); arbitrary values like `mt-[13px]` are audit flags ([theme docs](https://tailwindcss.com/docs/theme)). *Principle (renderer):* every spacing value in the token stylesheet is a multiple of one base unit; no one-off pixel values.
- [ ] **Related items sit closer together than unrelated items.** Spacing is itself a grouping device — "Spacing things further apart is a great way to create distinction between groups of elements without introducing any new UI at all" ([*7 Tips* §4](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). *Check:* for any element, the gap to its own group's members is strictly smaller than the gap to the next group.
- [ ] **A label and its control are one group: gap of `mt-2` (8px) between them, never 0.** All three free form components wrap the control in `<div class="mt-2">` under the label ([sign-in Simple](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms), [input group](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/input-groups)). *Principle:* label→control gap ≈ 0.5rem; visibly smaller than the field→field gap.
- [ ] **Helper text sits ≥ 8px below its control (`mt-2`–`mt-3`) — in every state, including pre-filled/re-edit.** The free Stacked form's helper line is `mt-3 text-sm/6 text-gray-600` under its textarea ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)). **Catches seed finding (a):** re-open a completed wizard step and measure the gap between the filled field and the helper/error line; 0px fails. *Principle:* helper/error text keeps its 8–12px offset from the control regardless of fill or validation state.
- [ ] **Field-to-field spacing is 24–32px** (`space-y-6` in the free sign-in form; `gap-y-8` grid in the free Stacked form) — clearly larger than the 8px label→control gap ([sign-in](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms), [form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)). *Principle:* between-field gap ≈ 3–4× the within-field gap.
- [ ] **Section-to-section spacing is larger still: `space-y-12` (48px) between form sections**, with each section's heading and description tight together (`mt-1`) ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)). *Principle:* the spacing ladder within a page is monotonic — intra-group < inter-field < inter-section.
- [ ] **Prefer white space (or a background change / shadow) over borders for separation.** "Use fewer borders … use a box shadow, use two different background colors, add extra spacing" ([*7 Tips* §4](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886); demonstrated on [refactoringui.com](https://refactoringui.com/)). If an element has both a border and a distinct background, try removing the border. *Note:* the famous "start with too much white space, then remove it" formulation is a paid-book chapter; the free-source proxy is this item — when separation is unclear, the audit remedy is **more space**, not more lines.
- [ ] **Action rows are separated from the form body** (`mt-6` before the button row in the free Stacked form) and buttons within the row are spaced `gap-x-6` ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)).
- [ ] **List rows breathe symmetrically**: the free stacked list gives each row `py-5` (20px above and below) with `divide-y` hairlines, and only `mt-1` between a row's title and its meta line ([stacked lists](https://tailwindcss.com/plus/ui-blocks/application-ui/lists/stacked-lists)). *Principle:* row padding ≥ 4–5× the internal title→meta gap.

## 2. Type scale & hierarchy

Default scale, from the [font-size docs](https://tailwindcss.com/docs/font-size) (v4 tokens `--text-*`, each with a paired `--text-*--line-height`):

| Class | Size | Default line-height |
|---|---|---|
| `text-xs` | 0.75rem (12px) | calc(1/0.75) → 16px |
| `text-sm` | 0.875rem (14px) | calc(1.25/0.875) → 20px |
| `text-base` | 1rem (16px) | calc(1.5/1) → 24px |
| `text-lg` | 1.125rem (18px) | calc(1.75/1.125) → 28px |
| `text-xl` | 1.25rem (20px) | calc(1.75/1.25) → 28px |
| `text-2xl` | 1.5rem (24px) | calc(2/1.5) → 32px |
| `text-3xl` | 1.875rem (30px) | calc(2.25/1.875) → 36px |
| `text-4xl` | 2.25rem (36px) | calc(2.5/2.25) → 40px |
| `text-5xl`–`text-9xl` | 3 / 3.75 / 4.5 / 6 / 8rem | 1 |

- [ ] **Every font size on screen is a step from one scale** (builder: the `--text-*` tokens above; no `text-[15px]` without a written reason). *Principle (renderer):* the token stylesheet's sizes form a single ratio-ish ladder equivalent to the table above; no orphan sizes.
- [ ] **Hierarchy is made with weight and color before size.** "Instead of leaving all of the heavy lifting to font size alone, try using color or font weight to do the same job" ([*7 Tips* §1](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). *Check:* secondary text is distinguished by `text-gray-500`-class color or lighter weight, not by dropping two size steps.
- [ ] **At most 2–3 text colors** for content: dark-but-not-black for primary, a grey for secondary, a lighter grey for ancillary ([*7 Tips* §1](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). Free-component anchors: `text-gray-900` primary / `text-gray-600` descriptions / `text-gray-500` meta ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts), [stacked lists](https://tailwindcss.com/plus/ui-blocks/application-ui/lists/stacked-lists)).
- [ ] **At most two font weights in the UI: normal (400/500) and emphasis (600/700). Never below 400 for UI text** — "Stay away from font weights under 400 for UI work"; de-emphasize with lighter color or smaller size instead ([*7 Tips* §1](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). Weight tokens: `--font-weight-*` 100–900 ([theme docs](https://tailwindcss.com/docs/theme)).
- [ ] **Heading sizes match their level of the free components**: page title `text-2xl/7 font-bold` (`sm:text-3xl sm:tracking-tight`) ([page headings](https://tailwindcss.com/plus/ui-blocks/application-ui/headings/page-headings)); section title `text-base/7 font-semibold` with `mt-1 text-sm/6 text-gray-600` description ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)). *Principle:* titles gain prominence chiefly through weight (semibold/bold); one size step per hierarchy level is enough.
- [ ] **Body/label text is `text-sm` (14px) with a 6-unit (24px) line-height (`text-sm/6`); meta text is `text-xs/5`** — the pervasive pattern across all five free components. *Principle:* body ≈ 14–16px with line-height ≈ 1.4–1.5; captions one step down.
- [ ] **Line-height shrinks as size grows**: leading tokens run `--leading-tight: 1.25` → `--leading-loose: 2`, and display sizes `text-5xl`+ default to line-height 1 ([theme](https://tailwindcss.com/docs/theme), [font-size](https://tailwindcss.com/docs/font-size)). *Check:* no display-size text with body-size leading and vice versa.
- [ ] **Text columns are width-constrained for readable measure.** Free components cap forms at `max-w-sm` (24rem) / `max-w-2xl` (42rem) containers ([sign-in](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms), [form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)); the official typography plugin bakes a `max-width` into every `prose` size "to keep the content as readable as possible" (65ch in its source) ([tailwindcss-typography](https://github.com/tailwindlabs/tailwindcss-typography)). *Principle:* bio/description text never spans the full viewport; measure stays roughly ≤ 65–75 characters.

## 3. Color & contrast

- [ ] **All colors come from an 11-step palette (50 lightest → 950 darkest) per family** — Tailwind ships each family with shades 50, 100, …, 900, 950, exposed as `--color-*` tokens ([colors docs](https://tailwindcss.com/docs/colors)). *Principle (renderer):* the token stylesheet defines an ordered light→dark ramp per hue; every color used is a ramp member, not an ad-hoc hex.
- [ ] **The app owns three palette roles: greys, one primary, and semantic accents** — "greys, 8–10 shades", "primary… 5–10 shades", accents for destructive/warning/success states ([Building Your Color Palette](https://www.refactoringui.com/previews/building-your-color-palette)). *Check:* no second "primary" hue competing with the brand hue.
- [ ] **Shades carry hierarchy on a single hue**: light shades (50–200) for tinted backgrounds, mid shades (400–600) for interactive elements, dark shades (700–950) for text ([colors docs](https://tailwindcss.com/docs/colors)). *Check:* emphasis differences use shade steps of the same hue, not new hues.
- [ ] **No grey text on colored backgrounds.** On a colored surface, de-emphasize with white at reduced opacity, or hand-pick a same-hue color adjusted in saturation/lightness — "Making the text closer to the background color is what actually helps create hierarchy, not making it light grey" ([*7 Tips* §2](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). *Renderer check:* on the generated page's colored link buttons and hero backgrounds, secondary text must be background-derived, never `gray-400/500`.
- [ ] **Text meets WCAG contrast: ≥ 4.5:1 body, ≥ 3:1 for large text** ([WCAG 2.2 SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)); interactive component boundaries and focus indicators ≥ 3:1 against adjacent colors ([SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)). *Renderer check:* run the palette logic's actual output pairs (user-chosen background × text) through a contrast checker — especially auto-derived button text.
- [ ] **Dark mode flips by shade, not by inversion**: the documented pattern is `bg-white → dark:bg-gray-800`, `text-gray-900 → dark:text-white`, `text-gray-500 → dark:text-gray-400` ([dark-mode docs](https://tailwindcss.com/docs/dark-mode)); dark-surface inputs use translucent fills and borders (`bg-white/5`, `outline-white/10`, labels `text-gray-100`) ([sign-in Simple, dark](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms)). *Principle:* each token has a dark counterpart one-to-two shade steps softened, not a naive invert.
- [ ] **Palette shades are tuned by eye, not formula** — "Trust your eyes, not the numbers" ([Building Your Color Palette](https://www.refactoringui.com/previews/building-your-color-palette)); Tailwind's own ramps are perceptually tuned in OKLCH ([colors docs](https://tailwindcss.com/docs/colors)). *Renderer check:* derived shades (hover states, tints) should be generated in a perceptual space or hand-checked, not naive RGB math.
- [ ] **Accent color appears as deliberate flair, sparingly**: accent borders (left edge of an alert, active nav item, top of layout) are the sanctioned way to add color to a bland region ([*7 Tips* §6](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)).

## 4. Button hierarchy

Free-source recipes (verbatim from free Tailwind Plus components — the [buttons category](https://tailwindcss.com/plus/ui-blocks/application-ui/elements/buttons) itself is entirely paid; its previews only confirm the variant set: primary, secondary, soft, with icons, rounded, circular):

- **Primary**: `rounded-md bg-indigo-600 px-3 py-2 text-sm font-semibold text-white shadow-xs hover:bg-indigo-500 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-indigo-600` ([form layouts "Stacked"](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts), same recipe in [page headings](https://tailwindcss.com/plus/ui-blocks/application-ui/headings/page-headings)).
- **Secondary**: `rounded-md bg-white px-3 py-2 text-sm font-semibold text-gray-900 shadow-xs inset-ring inset-ring-gray-300 hover:bg-gray-50` ([page headings](https://tailwindcss.com/plus/ui-blocks/application-ui/headings/page-headings), [form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)).
- **Tertiary** ("Cancel"): `text-sm/6 font-semibold text-gray-900` — link-style, no background, no ring ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)).
- **Full-width form primary**: `flex w-full justify-center rounded-md bg-indigo-500 px-3 py-1.5 text-sm/6 font-semibold text-white …` ([sign-in Simple](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms)).

Checklist:

- [ ] **Actions are styled by hierarchy, not only semantics** — "Most pages only have one true primary action, a couple of less important secondary actions, and a few seldom used tertiary actions" ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). *Check per screen:* exactly one solid high-contrast button; everything else steps down.
- [ ] **Primary = solid, high-contrast fill** in the brand hue, white text, semibold ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886); recipe above). *Principle:* highest-contrast fill on the page belongs to the single primary action.
- [ ] **Secondary = clear but not prominent: outline/soft treatment** — white/soft background + neutral ring, same radius/padding/typography as primary ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886); recipe above). **Catches seed finding (b):** a "We don't need one" button must match this recipe — same `rounded-md`, same `px-3 py-2 text-sm font-semibold`, visible `inset-ring`-style border — differing from the primary only in fill. A button that is neither solid-primary nor this secondary recipe fails.
- [ ] **Tertiary = link-styled**: "Styling these actions like links is usually the best approach" ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)); the free Stacked form's Cancel keeps button typography (`text-sm/6 font-semibold`) but drops fill and ring.
- [ ] **Destructive ≠ automatically big red.** Give delete a secondary/tertiary treatment unless it is the page's primary action (e.g. inside a confirmation dialog) — then it gets the solid red primary treatment ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)).
- [ ] **Sizing/padding is consistent across a row**: standalone buttons `px-3 py-2 text-sm font-semibold rounded-md`; in-form/full-width buttons `px-3 py-1.5 text-sm/6`; siblings in one action row share height, radius, and weight (free recipes above). *Principle:* all buttons on a screen share one padding/radius/type spec per size variant.
- [ ] **Hover and focus are defined for every button**: fill shifts one shade on hover (`bg-indigo-600 → hover:bg-indigo-500`, `bg-white → hover:bg-gray-50`) and focus shows the shared `focus-visible:outline-2 focus-visible:outline-offset-2` ring (free recipes above). *Principle:* hover = one ramp step; focus = 2px offset outline in the brand hue.

## 5. Form field anatomy

Canonical free-source anatomy (label → control → helper/error), assembled from the free [sign-in Simple](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms), [Stacked form layout](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts), and [free input group](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/input-groups):

```html
<label for="x" class="block text-sm/6 font-medium text-gray-900">Label</label>
<div class="mt-2">
  <input class="block w-full rounded-md bg-white px-3 py-1.5 text-base text-gray-900
                outline-1 -outline-offset-1 outline-gray-300 placeholder:text-gray-400
                focus:outline-2 focus:-outline-offset-2 focus:outline-indigo-600 sm:text-sm/6" />
</div>
<p class="mt-3 text-sm/6 text-gray-600">Helper text.</p>
```

- [ ] **Order is always label → control → helper/error**; label is `block` above the control (free components above). *Principle:* the reading order of a field is name, input, explanation — never explanation first, and helper never doubles as placeholder only.
- [ ] **Label spec: `text-sm/6 font-medium text-gray-900`** (dark surface: `text-gray-100`) — one size below body controls, medium weight (free components above). *Principle:* labels are smaller/medium-weight, clearly attached to their control (8px gap) per §1.
- [ ] **Control spec: `rounded-md px-3 py-1.5`, `text-base` on mobile stepping to `sm:text-sm/6`, resting border `outline-1 outline-gray-300`, `placeholder:text-gray-400`** (free components above). Placeholder is lighter than entered text and than helper text. *Principle:* inputs share one radius, one padding, one resting-border grey everywhere.
- [ ] **Focus state: border thickens and recolors in place — `focus:outline-2 focus:-outline-offset-2 focus:outline-indigo-600`** — same brand hue as the primary button's ring (free components above; the [@tailwindcss/forms plugin](https://github.com/tailwindlabs/tailwindcss-forms) exists precisely to normalize controls so utilities like these apply). For composed inputs (prefix/suffix), the **wrapper** carries the focus ring: `has-[input:focus-within]:outline-2 … outline-indigo-600` ([free input group](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/input-groups)). *Principle:* one focus treatment across every control and button, ≥ 3:1 contrast ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)).
- [ ] **Helper text: `mt-3` (≥ `mt-2`) below the control, `text-sm/6 text-gray-600`** — smaller/greyer than the label, never touching the control ([Stacked form](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)). **Catches seed finding (a)** together with §1: verify in the re-edit/pre-filled state specifically.
- [ ] **Error message occupies the helper slot with the same spacing (`mt-2`/`mt-3`, `text-sm`), colored from the semantic red ramp, with the control's border switched to the same red.** The exact "Input with validation error" component is paid ([input groups](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/input-groups) — noted as paid); the free-source derivation: error red is a semantic accent ([Building Your Color Palette](https://www.refactoringui.com/previews/building-your-color-palette)), and layout parity with helper text follows §1's grouping rule. *Principle:* error text replaces (not stacks under) helper text at identical offset; field border and message share one red.
- [ ] **Don't add labels that restate obvious format** — email, URL, and price formats can self-identify; when a label adds nothing, consider combining label and value or de-emphasizing the label ([Labels Are a Last Resort](https://www.refactoringui.com/previews/labels-are-a-last-resort)). For the wizard: keep labels for inputs (accessibility), but audit display screens (preview, public page) for label-noise like "Bio:".
- [ ] **Inline affordances follow the free input-group pattern**: leading add-on text `text-gray-500` inside the field's single rounded/outlined wrapper — useful for the wizard's URL fields (`https://` prefix) ([free input group](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/input-groups)).
- [ ] **Secondary link inside a field row (e.g. "Forgot password?") sits on the label line, right-aligned, `font-semibold` in the brand hue** ([sign-in Simple](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms)) — the pattern for per-field auxiliary actions in the wizard.

## 6. Consistency rules

- [ ] **Stick to the theme tokens; arbitrary values need a written reason.** v4 utilities exist *because* of theme variables — a value outside `--spacing`, `--text-*`, `--radius-*`, `--shadow-*`, `--color-*` is off-system by definition ([theme docs](https://tailwindcss.com/docs/theme)). Builder: grep for `[`-bracket arbitrary values and hex literals; each hit needs a justification comment or a token. *Principle (renderer):* every rule in the token stylesheet references a token; no magic numbers in component rules.
- [ ] **One primary action per view** ([*7 Tips* §7](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). Audit each screen of the wizard, list, preview, and download screens: exactly one solid brand-colored button visible at a time.
- [ ] **One radius per component class**: controls and buttons all use `rounded-md` (0.375rem) in the free components; the radius ladder is `--radius-xs` 0.125rem → `--radius-4xl` 2rem ([theme docs](https://tailwindcss.com/docs/theme)). *Check:* inputs, buttons, and cards each map to a single radius token; mixed `rounded-md`/`rounded-lg` siblings fail. *Principle:* one radius value per element role, drawn from a small ladder.
- [ ] **One shadow ladder, used sparingly**: `--shadow-2xs` … `--shadow-2xl` ([theme docs](https://tailwindcss.com/docs/theme)); buttons use the smallest (`shadow-xs`) (free recipes, §4). Shadows should have vertical offset ("simulates a light source shining down from above") rather than big symmetric blurs ([*7 Tips* §3](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)) — Tailwind's defaults already encode this (e.g. `--shadow-md: 0 4px 6px -1px …`). *Principle:* elevation steps come from one ladder; all shadows share the same light direction.
- [ ] **One focus style app-wide**: every interactive element uses the `outline-2 + outline-offset` pattern in the brand hue (§4/§5 recipes). *Check:* no mix of `ring-*`, browser-default outlines, and custom glows.
- [ ] **Borders are the last resort for separation** — before accepting a border, check whether shadow, background shift, or spacing does the job ([*7 Tips* §4](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886); [refactoringui.com](https://refactoringui.com/)). Where hairlines are right (lists), use the lightest ramp step: `divide-y divide-gray-100` ([stacked lists](https://tailwindcss.com/plus/ui-blocks/application-ui/lists/stacked-lists)).
- [ ] **Alignment is consistent per context**: form labels and fields left-aligned in a single column; action row right-aligned (`flex items-center justify-end gap-x-6`) with tertiary before primary ([form layouts](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/form-layouts)); centered layouts (sign-in / public page) center *everything* in one `mx-auto max-w-*` column ([sign-in Simple](https://tailwindcss.com/plus/ui-blocks/application-ui/forms/sign-in-forms)). *Check:* no screen mixes centered headings with left-aligned bodies without intent.
- [ ] **Icons stay near their drawn size** — never scale a 16–24px icon to hero size; if a big slot needs a small icon, enclose it in a colored shape ([*7 Tips* §5](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886)). Free anchor: meta icons are `size-5` and `text-gray-400` next to `text-gray-500` text ([page headings](https://tailwindcss.com/plus/ui-blocks/application-ui/headings/page-headings)) — icons one shade lighter than their text.
- [ ] **Repeated elements are pixel-identical**: every wizard step's field anatomy (§5), every list row (§1), every button variant (§4) uses the same class string / token set. *Check:* diff the class lists of sibling instances; unexplained divergence fails. **Backstops seed finding (b)** — a one-off secondary button style is exactly this kind of divergence.
